# Evaluation methodology and honest claims

The fixed corpus includes AI-authored fictional support policies, a text-bearing two-page PDF, a previous cancellation policy, and verbatim Python `venv`/`zipfile` documentation from CPython v3.12.7 under the included PSF license. `data/source_manifest.json` records file hashes, titles, versions, origins and effective dates. No document or question is claimed human-reviewed.

The benchmark has 200 distinct question intents/families, including 55 insufficient-information cases (27.5%). There are 60 development and 140 final test questions. Related source/theme groups stay in one split, rather than distributing template-related questions randomly. Question intents share sources and are not 200 statistically independent observations. The final comparison also includes themes observed in the first exploratory development run; it is not represented as a pristine unseen holdout. See the decision log. Every question records its family and leakage group, track, type, expected status, reference, conditions and canonical evidence groups. `benchmarks/splits.json` freezes version 2; `experiment-decisions.md` records the integration exposure that required moving demo themes to development before final testing.

Gold labels contain source-file hashes and exact spans in canonical extracted text, independent of chunk IDs. The runner validates those spans against the stored extraction and resolves them for the current chunker. A relevant passage overlaps a span by at least min(24, span length) characters. Gold groups allow alternative spans; different required facts use different groups. Group credit requires at least 95% union coverage of one allowed span; duplicated overlap is not extra coverage. This strict span criterion can penalize partial paragraphs that semantically contain an answer; inspect such failures before changing labels, and make any change on development data first.

- Hit@5: answerable questions with any relevant item in the five returned passages, divided by answerable questions.
- Evidence-group Recall@5: mean fraction of required groups covered per answerable question.
- MRR@5: mean reciprocal rank of the first relevant passage among five returned results; zero when absent.
- Full-evidence@5: answerable questions for which all required groups are covered.
- Missing-information cases are excluded from retrieval relevance denominators; latency includes them. Returning a passage to a missing question is not an answer correctness failure by itself.

Every method uses the same snapshot, questions, authorized scope, candidate limit, chunker and model configuration. BM25 is real `rank_bm25.BM25Okapi`: Unicode case folding, preservation of hyphenated/underscored IDs, no stemming and no stop-word removal; k1=1.5 and b=0.75. Dense search is exact cosine of normalized MiniLM vectors. RRF uses one-based ranks, equal weights and constant 60; absent candidates contribute zero. Reranking rescoring is applied only to the top 20 fused candidates. It cannot recover missing candidates outside this pool.

Published results: `evidence/retrieval-test/report.md` plus all method JSONL files and the manifest. The final run has 103 answerable and 37 missing questions. Full evidence: BM25 0.8932, dense 0.9029, hybrid 0.9029, reranked 0.9223. Reranking improves this benchmark while increasing warm p95 retrieval time from hybrid 4.3 ms to 121.1 ms. The development-derived 0.85 full-coverage and 250 ms warm p95 targets were met on this machine; this is not a human semantic accuracy claim. Public versus authored tracks and question-type/group-count breakdowns are in `summary.json`.

Paired differences compare each question with BM25. The 1000 bootstrap draws resample entire source/theme groups (seed 42), including every related question, to avoid overconfidence from correlated variants. The small group count still limits inference. No nDCG is reported because graded labels are unavailable.

Answer evaluation is separate. `doculens evaluate-answers` freezes a stratified bounded sample using seed 42 and records real provider outputs, returned usage, prompts, citations and a separate automated semantic review. Correctness rubric: 0 wrong, 1 partial or missing a material condition, 2 correct with conditions. Claims are supported/unsupported/ambiguous. Reviews assess conditions, semantic citation support and coverage, and appropriate abstention. Wrong answered statuses on unanswerable cases and unnecessary abstention on answerable cases have distinct denominators. Technical/provider failures are reported separately. No fixture response may be scored as live generation.

The same local Qwen model is used as generator and judge when the free local judge is enabled. Record that limitation: self-judging may share errors. Manual calibration, human disagreement, and authoritative semantic accuracy are **unavailable**, not zero. The complete rubric/prompt is in the answer manifest. Provider-free tests prove schema/citation/reliability contracts, not LLM quality. A no-retrieval provider comparison is not currently run; the app's no-evidence short circuit is not presented as a provider baseline.

Performance reports specify hardware, warm-up, sample sizes, request concurrency, model commits, input lengths and failures. `evidence/load.json` is 100 warm loopback retrieval requests on the same question at concurrency 2, with real MiniLM and no generation: measured p50 about 60 ms and p95 about 113 ms. It does not estimate remote production capacity. Provider fees are zero for local Ollama; hardware/electricity are not priced. Unknown token/retry usage is not zero. No paid cloud price configuration or cost estimate is invented.
